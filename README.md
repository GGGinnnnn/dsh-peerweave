# Peerweave · dsh-peerweave

**Peerweave** 是一个 DeepSeek Harness（DSH）插件：让两台或多台电脑上的 DSH 通过加密点对点链路互联，并在工作区中显示在线节点、查看对方工作区历史、按三档权限只读访问文件，或与对方的 DSH 对话。

插件名 `Peerweave`，包名 `dsh-peerweave`。2026-11 查询 npm registry，`peerweave` 与 `dsh-peerweave` 均未被占用，未发现同名插件。

---

## 功能

- **多机互联**：直连 TCP（P2P）或通过 SSH 隧道连接；链路双向可用，一端能连上即可。
- **工作区显示**：当前会话输入框下方显示已连接 / 离线节点，带连接状态与授权等级；点击展开历史、文件、对话。
- **管理页**：设置 → Peerweave，管理密码、节点、邀请码、权限、共享目录、文件大小上限、审计记录。
- **查看对方工作区历史**：列出对方共享目录内的会话及消息，只读。
- **读取对方文件**：目录浏览 + 文本/二进制读取 + 「复制到我的工作区」；对方文件永远只读，插件没有写对方文件的任何操作。
- **文件大小上限**：由文件提供方设置（默认 16 MiB，硬上限 2 GiB），超限直接拒绝并返回实际上限；大文件通过 8 MiB 分块边读边写，不会一次性读进内存。
- **三档权限 + 密码验证**：每次修改权限都要输入安装时设置的密码；第三档必须等满 10 秒才能确认。
- **安装密码**：首次使用必须创建密码；密码用于加密本机身份私钥，并保护所有权限变更。
- **审计**：权限变更、配对、连接、设置修改都记录时间与对象（最近 30 条在设置页展示）。

## 安装

要求 DSH `0.2.2-rc.1` 或兼容版本（Web 客户端 + `settings.section` / `conversation.composer.dock` 插槽）。

```bash
git clone https://github.com/GGGinnnnn/dsh-peerweave.git
```

然后在 DSH 中把该目录作为本地 bundle 安装（Plugin Manager → 安装本地 bundle，或使用 `plugin_manager` 的 `install_bundle`，`target` 指向仓库目录）。安装会写入当前配置档的 `package.json` 与 bundle 列表。

安装后：

1. **重启 DSH** 以加载 Host 构建（本地目录安装需要新的模块代际）。
2. 刷新页面以加载 Client UI。
3. 打开 设置 → Peerweave（或点击输入框下方的 **Set up Peerweave / 设置 Peerweave**），创建密码。
4. 以后每次 DSH 重启，插件都处于锁定状态；在设置页或输入框下方的锁形入口输入一次密码解锁后，才会开始监听和自动重连。身份私钥受密码保护，这是有意的取舍。

> 忘记密码时：打开 设置 → Peerweave 的锁定页，在密码输入框下方使用 **「强制清除 Peerweave…」**。点击后进入二级确认，必须等满 10 秒才能确认；确认后插件恢复到刚安装、尚未设置密码的状态，身份密钥、密码、全部节点和所有设置都会被删除。也可以退出 DSH 后手动删除 `%DSH_HOME%\peerweave\<配置档>\state.json`。已知密码时可在设置页使用「清空一切」。

## 首次使用

1. **设置密码**（至少 8 位）。插件会生成 Ed25519 身份密钥，并用 `scrypt` 派生密钥 + AES-256-GCM 把私钥加密后写入状态文件。
2. **确认共享工作区**。首次创建密码时会自动采用最近一个真实会话的工作目录作为共享根目录；也可以在设置页手动填写（留空则退回默认工作区）。之后可随时修改，修改需要密码。
3. **A 机生成邀请码**（需要密码）。邀请码包含 A 的地址、监听端口、身份指纹和一次性配对密钥，10 分钟有效、只能使用一次。
4. 把邀请码通过可信渠道发给 B。**B 在 设置 → Peerweave → 加入另一台 DSH** 粘贴邀请码并加入；若 A 在 NAT 后，可勾选 SSH 隧道并填写 `user@host` 与 A 的监听端口。
5. 配对成功后，两端都会出现对方节点（默认第 0 档：仅链接，不允许任何读取）。双方分别设置「我授予对方的权限」。
6. 在输入框下方点击节点，即可按对方授予的档位查看历史 / 文件 / 对话。

### 连接方式

- **直连 TCP（默认）**：监听 `0.0.0.0:41337`（可在设置中修改）。跨网络时需要在路由器/防火墙放行该端口，或做端口转发。邀请码里的地址默认取自动检测的局域网 IPv4，可在设置页填写「供对方连接的地址」。
- **SSH 隧道**：加入邀请码时勾选「通过 SSH 隧道」，填写 `user@host` 和对方在 SSH 主机上的监听端口。插件调用系统 `ssh`：
  ```
  ssh -N -o BatchMode=yes -o ExitOnForwardFailure=yes \
      -o StrictHostKeyChecking=accept-new \
      -L 127.0.0.1:<临时端口>:127.0.0.1:<对方端口> user@host
  ```
  **SSH 私钥完全由 OpenSSH 管理**，插件不读取、不复制、不保存私钥；私钥的口令加密由 `ssh-agent` / OpenSSH 负责。隧道内仍然是 Peerweave 自己的加密链路，两层加密互不替代。

## 三档权限

| 档位 | 名称 | 对方能做什么 | 对方不能做什么 |
|---|---|---|---|
| 0 | 仅链接 | 看到你在线、获取你的名称/指纹/授权等级 | 读写任何内容 |
| 1 | 查看工作区 | 列出共享目录内的会话、读取会话消息（历史） | 读取文件、对话 |
| 2 | 读取文件 | 在第 1 档基础上，浏览目录、读取文件、复制文件到对方电脑上继续工作 | 修改/删除/写入你的文件（插件没有这类操作） |
| 3 | 与 DSH 对话 | 在第 2 档基础上，向本机 DSH 的访客会话发消息并获得回复 | 修改权限、绕过密码 |

- 每一档都在**服务端**校验；客户端 UI 只是展示。
- 权限变更流程：`prepare`（验证密码）→（第三档等待 10 秒）→ `commit`（**再次验证密码** + 一次性 nonce + 服务端时间校验）。提前确认会返回 `confirm-too-early`。
- 第三档的 10 秒由服务端强制，不是仅靠 UI 倒计时。

> **风险提示（第三档）**：对方会控制本机上一个真实的 DSH 智能体。该智能体可以使用本工作区允许的工具，包括读文件、执行命令等。请只授予完全信任的人；确认前请阅读设置页中的完整警告，并等满 10 秒。

## 安全设计

### 身份与配对

- 每台机器生成长期 **Ed25519** 身份密钥；指纹为 `SHA-256(公钥)`，界面显示为 `PW-xxxx-xxxx-xxxx-xxxx`。
- 邀请码内含邀请方指纹与一次性 32 字节配对密钥。加入方必须证明持有该密钥（`HMAC-SHA256` 覆盖握手摘要），邀请方因此可在不认识对方的情况下安全接受首次连接；加入方用邀请码中的指纹校验邀请方身份，防止中间人。
- 之后的连接只接受已信任指纹；身份不匹配立即拒绝。

### 链路加密

- 每次连接生成临时 **X25519** 密钥，双方做 ECDH；用 **HKDF-SHA256** 按方向派生两把 256 位密钥（A→B、B→A 不同）。
- 双方用 Ed25519 对握手摘要签名并互相验证，最后做 key confirmation。
- 所有业务帧使用 **AES-256-GCM**，12 字节隐式 nonce = 4 字节 0 + 64 位单调计数器，AAD 绑定会话 ID；计数器不匹配、重放、篡改都会导致解密失败并断开。
- 握手有超时，连接有心跳与 90 秒空闲回收。

### 密码与密钥存储

- 密码不明文保存；用 `scrypt(N=16384, r=8, p=1)` 派生主密钥，再用 HKDF 派生出状态加密密钥。
- 身份私钥（PKCS#8 PEM）用 AES-256-GCM 密封后存入状态文件；**密码错误 = GCM 认证失败**，不额外保存可离线暴力破解的哈希。
- 修改密码会重新派生并重新密封私钥。
- 密码尝试有限速：同一来源 5 次失败后锁定 30 秒；权限变更在 `prepare` 和 `commit` 各验证一次。

### 管理 API 防护

插件在本地 Web 服务上注册 `/peerweave` 路由（该路由位于页面认证之外），因此单独加了三层围栏：

1. `Host` 必须是回环地址（`127.0.0.0/8`、`localhost`、`::1`）。
2. 有 `Origin` 时必须与 `Host` 同源，`Sec-Fetch-Site: cross-site` 拒绝；并且必须带自定义头 `x-peerweave: 1`（跨站请求会触发预检而被拒）。
3. 除首次设置密码 / 解锁外，所有请求都要携带解锁后签发的**内存 token**（30 分钟滑动过期，不落盘）；权限变更还必须在请求体中再次提供密码。

### 文件访问

- 共享根目录之外的路径一律拒绝：拒绝绝对路径、盘符、`..`、NUL；对已存在路径做 `realpath` 包含性检查，防止符号链接逃逸。
- 只实现 `list / stat / read`，没有写入、删除、重命名接口。
- 先 `stat` 再按上限拒绝；内联读取最多 8 MiB，更大的文件必须通过分块复制传输（8 MiB/块，边读边写）；上限硬编码 2 GiB，默认 16 MiB。

### 对话（第三档）

- 每个远端节点会懒创建一个标题为 `Peerweave guest · <节点名>` 的访客会话，位于共享工作区；消息通过 `sessionController.prompt` 进入该会话，用 `wait` 等待结果并抽取 assistant 文本。
- 访客会话对用户可见、可审计；节点被移除或执行「清空一切」时会自动归档（archive）。
- 对话限速 4 条/分钟，单条 ≤ 4000 字符；远端调用超时 90 秒。

## 设置项

| 设置 | 说明 | 是否需要密码 |
|---|---|---|
| 单文件上限（MiB） | 别人可读取的最大文件；实际字节数会限制在 1 KiB–2048 MiB（2 GiB） | 是 |
| 监听端口 | 默认 41337；被占用时自动向后尝试 10 个端口并在界面显示实际端口 | 是 |
| 共享工作区根目录 | 空 = 默认工作区；必须是已存在目录 | 是 |
| 显示名称 | 其他节点看到的名字 | 是 |
| 供对方连接的地址 | 写进邀请码的主机名/IP；空 = 自动检测局域网 IPv4 | 是 |
| 自动重连 | 已知节点断线后按指数退避重连 | 是 |
| 修改密码 / 移除节点 / 清空一切 | — | 是 |

## Agent 工具

插件向本机 Agent 注册 4 个只读工具（权限变更仍是用户专属操作）：

- `peerweave_peers` — 列出节点、连接状态、双方授权。
- `peerweave_history` — 列出/读取远端共享工作区历史（需对方授予第 1 档+）。
- `peerweave_read_file` — 读取远端文件（需第 2 档+，受对方大小上限约束）。
- `peerweave_chat` — 给远端 DSH 发消息并取回回复（需第 3 档）。

插件锁定时，工具会提示用户先到 设置 → Peerweave 解锁。

## 数据位置与恢复

- 状态文件：`%DSH_HOME%\peerweave\<配置档>\state.json`（当前机器为 `C:\Users\Administrator\.dsh\peerweave\default\state.json`）。
- 包含：密封的 Ed25519 私钥、scrypt 参数、受信节点、未使用邀请码（10 分钟）、设置、审计。
- 备份该文件即可保留身份与节点信任；恢复后仍需输入密码解锁。
- 「清空一切」会删除身份、密码、全部节点与审计，且不可撤销；访客会话会先归档。
- **忘记密码**：锁定页的「强制清除 Peerweave…」按钮提供一条不需要密码的恢复路径。它使用同样的清除逻辑，但必须先点击、再等满 10 秒二级确认（服务端强制，服务端另校验确认短语 `ERASE`，UI 自动附带）；随后恢复到首次设置密码前的初始状态。

## Token 消耗

Peerweave 的浏览界面和模型上下文是分开的：

- **在 dock / 设置页查看对方历史、目录、文件内容：0 token。** 这些数据通过加密 Peerweave 链路直接进入本地 UI，不经过任何 LLM，也不写入会话上下文；且没有后台轮询同步，只有你点击时才读取。
- **本地 Agent 调用 `peerweave_history` / `peerweave_read_file` 工具：会产生 token。** 工具返回值作为 tool result 进入当前会话，消耗量取决于返回内容的大小。历史读取有上限（最多 100 条消息、约 150 KB 文本），文件内联读取上限 8 MiB——8 MiB 文本可能是数十万 token，建议只让 Agent 读小文件，大文件用「复制到我的工作区」落到磁盘后再按需处理。
- **与对方 DSH 对话（第三档）**：Chat 面板只是收发消息，**本机不消耗 token**；但对方机器会运行一次真实 Agent turn，消耗**对方电脑**的模型 token。若用本机 Agent 的 `peerweave_chat` 工具发起，则对方的回复还会进入本机会话，双方都产生 token。
- 对方工作区的历史/文件不会自动注入系统提示，也不会在后台同步；不存在「一连接就消耗大量 token」的行为。

## 已知限制

- **没有中继服务器**：两端网络必须能直连，或使用 SSH 隧道；插件不做打洞/NAT 穿透。
- **内联读取上限 8 MiB**：更大的文件不能直接在预览里全文读取，必须使用「复制到我的工作区」走分块传输（单文件硬上限 2 GiB）。
- **单一共享根目录**：一个密码库对应一个共享根；如果想让不同节点看不同目录，需要分配置档运行。
- **第三档是真实控制权**：访客智能体拥有常规工具权限；用户可拒绝其触发的审批，但不应把第三档授予不可信对象。
- **访客会话会出现在会话列表**：标题带 `Peerweave guest`，便于发现；移除节点/重置时归档。
- **首次共享目录是启发式**：采用最近真实会话的 cwd；多工作区用户请在设置中显式指定。
- **本地目录安装需要重启**：Host 代码在进程内以模块代际加载；更新源码后需重启 DSH。Client 代码刷新页面即可。
- **SSH 隧道依赖系统 `ssh`**：Windows 需启用 OpenSSH Client；若目标不在 `known_hosts`，使用 `accept-new`（TOFU）。
- 未做 IPv6 专门适配；监听 `0.0.0.0`，连接使用邀请码中的 IPv4/主机名。
